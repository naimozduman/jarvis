## Proposal identity

Proposal: V5-005. Status: proposed, not accepted. Acceptance evidence: none. Repository number: unassigned. Owner: Naim. Base repository must be reconciled at J5-M00.

## Context

Existing cost guards exist, but concurrent autonomous jobs need reservation and loop termination.

## Decision

Preserve existing guards. Add atomic settled-plus-reserved accounting per owner, period and job, plus bounded retries and no-progress termination.

## Alternatives considered

A config number without current usage is not a spend boundary. Silently downgrading a model is not equivalent to stopping a loop.

## Security and privacy impact

Unknown paid accounting blocks new billable work. No budget proposal counts as owner consent.

## Consequences

This adds explicit review and test work at the affected boundary. It reduces ambiguous authority but does not eliminate operator error, malicious administrators, provider defects, or test blind spots. The owning design is [COST_AND_MODEL_POLICY.md](../../../security/COST_AND_MODEL_POLICY.md).

## Migration and compatibility

Owner approves profile first. Then wire durable reservations into every billable adapter and test concurrency. Preserve current implementations until the relevant mission proves compatibility. A staged rollback must restore the previous accepted implementation without reviving expired authority.

## Acceptance evidence

Pending. Require exact base/head, test report, owner authorization and trusted gate result. Do not fill these with a fabricated success.

## Supersession

None activated. At promotion, identify any actual accepted ADR to supersede and assign a repository ADR number. This proposal does not supersede history by filename.
