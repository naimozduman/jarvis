## Proposal identity

Proposal: V5-001. Status: proposed, not accepted. Acceptance evidence: none. Repository number: unassigned. Owner: Naim. Base repository must be reconciled at J5-M00.

## Context

Codex has broad project context but must not unilaterally redefine safety requirements.

## Decision

Use a trusted-base data-only gate and detached exact-change owner signatures for protected changes.

## Alternatives considered

Ordinary PR checks that execute the candidate validator permit self-approval. Making all docs read-only blocks legitimate evidence updates.

## Security and privacy impact

Protect normative docs, critical runtime guards, baseline tests and checker policy. Keep operational evidence writable but incapable of granting authority.

## Consequences

This adds explicit review and test work at the affected boundary. It reduces ambiguous authority but does not eliminate operator error, malicious administrators, provider defects, or test blind spots. The owning design is [TRUST_BOOTSTRAP.md](../../../security/TRUST_BOOTSTRAP.md).

## Migration and compatibility

Bootstrap outside the builder credential boundary. No protection is assumed installed. Preserve current implementations until the relevant mission proves compatibility. A staged rollback must restore the previous accepted implementation without reviving expired authority.

## Acceptance evidence

Pending. Require exact base/head, test report, owner authorization and trusted gate result. Do not fill these with a fabricated success.

## Supersession
