# ADR 0023: owner-authored baseline review

Date: 2026-10-02

Status: Implemented within the existing owner-review and canonical memory boundaries. This does
not activate any owner's constitution item or expand execution authority.

The production owner has no useful durable bootstrap baseline. Existing onboarding answers,
memory candidates/evidence, typed memory records, constitution proposals/versions, projects,
people, open loops and commitments already provide the required storage. The missing piece is
a private conversational path from deliberate owner input to a delivered, numbered review and
explicit confirmation. No parallel profile table, migration, external import or new executor is
needed.

The existing Brain call may extract proposed items from the current verified owner's message.
Its action intents and activation/success wording have no effect in this path. The server checks
current-message evidence and produces the review. Goals, rules, prohibitions, standing promises
and recurring obligations are draft constitution candidates; uncertainty remains a hypothesis.
Explicit exact confirmation of the current provider-accepted review performs the canonical
promotion. A review accepted after the confirming input arrived cannot authorize that input.
Confirmation, corrections, review and replay recovery make no model call.

Existing onboarding answers retain item identities and draft review revisions. Corrections
supersede candidates and evidence; approved entities remain unchanged until fresh confirmation.
Promotion uses the existing memory policy and versioned constitution state. Near-term commitment
creation uses the existing internal action/policy/audit path and creates no reminder or scheduled
execution. Excluding a baseline item does not cancel an existing commitment. Canonical writes,
reply, audit and request completion finalize atomically and recover idempotently.

The existing bounded context assembler selects approved canonical records without larger
budgets. Private people/relationship material requires an explicit named owner request, including
when reclassified as a hypothesis, rule or commitment. Restricted material is redacted and cannot
enter accountability guidance. Source/review messages and later turns consuming scoped records
are omitted from general history using canonical request and context-manifest bindings. Correction
and supersession retain the private scope.

Synthetic production-service tests prove approval, correction, replay, rollback, current enrollment,
private scope and later context selection. They do not claim a live owner baseline, provider prose
quality, a longitudinal evidence window or Phase 3.8 completion.
