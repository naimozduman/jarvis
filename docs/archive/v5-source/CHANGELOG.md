# 5.0.0 candidate

V5 is an engineering takeover and migration candidate, not a new runtime deployment. It starts with preservation and exact source evidence, installs trust, classifies old subsystems, reconciles Brain/infrastructure, then builds the Personal OS by bounded missions.

New: a complete generated product reference with requirement IDs and acceptance conditions; progressive topic context; a single descriptive STATE and local compare-and-swap updater; 24 mapped missions; signed mission prerequisite validation; dummy-key lifecycle verifier; trusted-time reference tests; restoration, incident, health and supply-chain procedures; artifact retirement proposals; explicit source keep/repair targets.

Retained: V4.1 protected-by-default promotion, evidence authentication, isolated worker tooling, 15 draft runtime contracts, deliberate owner policy non-enrollment, and original archival material.

Removed from active navigation: V3/V4 mission stubs and duplicate prompt retirement entrypoints. Runtime prompt candidates now occupy `prompts/runtime/modules/`. Draft schemas occupy `schemas/drafts/`, preserving wire versions independently from pack generation. No live prompt loader or runtime schema import was replaced.

Original V4.1 validation records remain historical under `reference/v4.1/`. Current results belong to `validation/` and VALIDATION_REPORT only. Original source PDFs/DOCX are archival research/product inputs, not current instructions or provider proof.

See `governance/VERSION_TRANSITION.json` for per-path treatment. This candidate changes no repository, deployment, account, key, permission or database by being generated.
