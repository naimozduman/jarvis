## Proposal identity

Proposal: V4-004. Status: proposed, not accepted. Acceptance evidence: none. Repository number: unassigned. Owner: Naim. Base repository must be reconciled at J4-M00.

## Context

Authentic taps do not prove the owner understood a model-authored description.

## Decision

Render a canonical first-party approval view. Require recent step-up for high-impact actions and lease creation. No high-impact action uses a lease in this profile.

## Alternatives considered

In-thread high-impact approval mixes persuasive chat with authority. Permanent standing grants accumulate forgotten scope.

## Security and privacy impact

Display exact targets and effects. Reject mismatched snapshots, stale sessions and wildcard lease scope.

## Consequences

This adds explicit review and test work at the affected boundary. It reduces ambiguous authority but does not eliminate operator error, malicious administrators, provider defects, or test blind spots. The owning design is [APPROVAL_MODEL.md](../../../../docs/APPROVAL_MODEL.md).

## Migration and compatibility

Approval and lease reference functions in this pack are executable specifications, not a deployed identity service. Preserve current implementations until the relevant mission proves compatibility. A staged rollback must restore the previous accepted implementation without reviving expired authority.
