## Proposal identity

Proposal: V4-006. Status: proposed, not accepted. Acceptance evidence: none. Repository number: unassigned. Owner: Naim. Base repository must be reconciled at J4-M00.

## Context

Reusable mission templates were confused with completed project phases.

## Decision

Use stable J4-M IDs, one roadmap graph and separate run records tied to exact repository commits. Maintain one mutable current handoff.

## Alternatives considered

Marking every template active invites replay. Logging every minor session as a milestone obscures meaningful history.

## Security and privacy impact

Completing a template never grants live credentials or starts the next mission.

## Consequences

This adds explicit review and test work at the affected boundary. It reduces ambiguous authority but does not eliminate operator error, malicious administrators, provider defects, or test blind spots. The owning design is [SESSION_CONTINUITY.md](../../../../docs/SESSION_CONTINUITY.md).

## Migration and compatibility

Reconcile real phase evidence at M00. Retire V3 mission entrypoints with explicit redirects. Preserve current implementations until the relevant mission proves compatibility. A staged rollback must restore the previous accepted implementation without reviving expired authority.

## Acceptance evidence

Pending. Require exact base/head, test report, owner authorization and trusted gate result. Do not fill these with a fabricated success.

## Supersession

None activated. At promotion, identify any actual accepted ADR to supersede and assign a repository ADR number. This proposal does not supersede history by filename.
