## Proposal identity

Proposal: V4-003. Status: proposed, not accepted. Acceptance evidence: none. Repository number: unassigned. Owner: Naim. Base repository must be reconciled at J4-M00.

## Context

V3 draft schemas lacked an adoption ledger and blurred model intent with execution authority.

## Decision

Separate ActionIntent, ProposedAction, ExecutionAuthorization and approval resolution. Register contract IDs, wire versions and lifecycle evidence.

## Alternatives considered

Adding ownerId or approved=true to model output trusts the wrong principal. Replacing active schemas blindly breaks consumers.

## Security and privacy impact

Ownership, exact payload binding, TTL and current policy epoch remain server-derived.

## Consequences

This adds explicit review and test work at the affected boundary. It reduces ambiguous authority but does not eliminate operator error, malicious administrators, provider defects, or test blind spots. The owning design is [SCHEMA_EVOLUTION.md](../../../../docs/SCHEMA_EVOLUTION.md).

## Migration and compatibility

Keep old runtime schemas active. Migrate producers and consumers through compatibility tests. Preserve current implementations until the relevant mission proves compatibility. A staged rollback must restore the previous accepted implementation without reviving expired authority.

## Acceptance evidence

Pending. Require exact base/head, test report, owner authorization and trusted gate result. Do not fill these with a fabricated success.

## Supersession

None activated. At promotion, identify any actual accepted ADR to supersede and assign a repository ADR number. This proposal does not supersede history by filename.
