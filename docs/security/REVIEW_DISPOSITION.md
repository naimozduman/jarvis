# V5 disposition

## Changes accepted into the candidate engineering system

Progressive builder context, one descriptive STATE handoff, the explicit existing-code disposition program and stable V5 missions replace the assumption that an overlay installs itself. There are dedicated missions for device policy, executor safety, workers, Night Mode and browser work. The complete product reference remains a source for relevant requirements rather than mandatory full-context overhead.

V4.1 protected-default promotion, exact-head workflow evidence, finite lease contracts, model-intent/server-authority separation, identity challenge procedure, trusted approval UI requirements and isolated-worker tooling remain intact. V5 adds a data-only mission admission verifier, purpose-separated completion receipts, key lifecycle transition verification, trusted-time examples, artifact retirement review and practical restoration/incident runbooks.

## Findings corrected by source inspection

The existing CI explicitly runs Brain, transport, orchestration and bridge eval commands. The budget guard is implemented, not a missing concept. The policy module has owner, kill, finance, unknown-action and risk-class guards. V4.1 changed 37 V4 files and added 19; it was not a purely additive patch. Runtime prompt retirement notices are not competing prompt bodies. WhatsApp challenge enrollment and keyed opaque identity references already have a written procedure. Historical zero-cost documentation is not active cost authority.

Those corrections do not certify deployment. They prevent replacing working controls because a review inspected the wrong layer.

## New focused source findings

At the pinned source checkpoint, prompt versions depend on module IDs and declared versions rather than exact content. Context admission sums selected record text rather than the complete serialized model request. Conversation duplicate handling returns an existing request even when its decision/response are incomplete. Model-budget dependencies are optional in the conversation service and usage values have fallback zeros. These are reconciliation targets, not claims of a demonstrated production exploit. J5-M03, M04 and M05 require actual-path reproductions before repair.

See `governance/RECONCILIATION.json` for exact paths, Git blob hashes, scope and required proof.

## Kept as owner decisions

Budget amounts, interruption density, retention periods, recovery-material custody, optional delays on authority expansion, broad authority and enabled external capabilities remain unapproved. Reviewers do not grant consent. No mandatory hardware purchase, M-of-N human arrangement or blanket 24-hour action delay was silently imposed.

## Not claimed solved by packaging

The private local worktree, installed provider state, actual database reservations, deployed voice cancellation, first-party approval UI, real shutdown propagation, backup restore, key custody and networked Codex isolation are unverified. Rootless Docker support remains a supplied launcher/probe, not a performed local-machine certification.

## Review coverage and stopping rule

V5 contains a requirement-to-mission trace, a source disposition map and tests for its tools. It does not certify absence of all design defects. A new mechanism belongs in the next mission only when it addresses an upcoming risk, a reproduced failure or an explicit product requirement. No file-count target governs quality.
