# Telegram initial typing at ingress

The previous initial `sendChatAction("typing")` ran in the canonical conversation worker. It therefore waited for ingress composition, event persistence, Convex dispatch, worker composition, inbound-message persistence and exact enrollment. Live evidence at 18:23 UTC shows canonical ingress at 18:23:49.496 and initial typing attempted at 18:23:51.730, accepted at 18:23:52.139. A second observed Bot API typing request took 1,510 ms, independently of orchestration.

Initial typing now belongs to authenticated Telegram ingress. The webhook validates the secret and private direct text shape, persists the existing atomic event/job receipt (provider update idempotency), and uses the same canonical inbound repository as the worker (provider message idempotency). Only the inserting update invocation with a new message may check exact existing enrollment and launch typing. No orchestration signal is sent before that launch. The atomic event/job persistence contract is unchanged; processing that receipt remains asynchronous.

The recipient comes from the just-authenticated private update, with `chat.id === from.id`, after persisted evidence and exact enrollment. It does not enter logs or Brain context. The Bot API request is detached and retained with Vercel `waitUntil`; it has no database access or authority and cannot block queue signalling. Failed initial typing is not retried by webhook replay. The conversation worker refreshes typing every four seconds only while the authoritative turn is active and no longer emits another initial request. Drafts and final delivery are unchanged.

`telegram.turn.timing` records safe stage names, internal event/request/delivery IDs and local monotonic clocks. A segment starts before runtime composition in the Vercel shell. Same-segment durations use `performance.now()`. Separate function invocations are correlated using internal IDs and timestamped evidence; clocks from different processes must not be subtracted. Queue latency is a correlated timestamp interval, not claimed to be a cross-process monotonic duration.

Coverage includes authentication/private-shape guards, committed persistence before typing, exact enrollment, provider update and message replay, pending/failed typing independence, four-second worker refresh and cancellation, monotonic telemetry, and the existing full CI/database gates. Live timing verification follows deployment with one fresh owner message. Model routing, Brain/action semantics, policy and final-send accounting are unchanged.
