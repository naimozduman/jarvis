## Phase 1 — Individual System Breakdowns

### 1. Hermes Agent (Nous Research, MIT) — the runtime most builds are a skin over

- **Pipeline**
  - Ingress: `gateway/` bots (Telegram/WhatsApp/Discord via `channel_directory.py`, `delivery.py`), `hermes_cli/gateway.py`, TUI/desktop, `run_agent.py`
  - Turn: `conversation_loop.py::run_conversation()` → `_run_conversation_turn()` → `turn_preflight.py` → `turn_request_assembly.py::assemble_api_request()` (system prompt, `build_memory_context_block()`, skill payloads) → `turn_api_call.py` → `turn_tool_round.py::run_tool_round()` (returns `ToolRoundVerdict`) → `turn_finalizer.py::finalize_turn()`
  - Resilience wrappers around every turn: `iteration_budget.py`, `interrupt_control.py`, multi-strategy `context_compressor.py`, `error_classifier.py`, `repetition_guard.py`
  - Background: `periodic_scheduler.py` (cron), `async_delegation.py` (subagents); learning loop: `learn_prompt.py::build_learn_prompt()` reflective phase → `curator.py` background curator (`get_interval_hours()`, `get_min_idle_hours()`) → `learning_graph.py` (`SkillNode` from SKILL.md `related_skills`)
  - Skills: `SKILL.md` YAML frontmatter (`name/description/version/platforms/metadata.hermes.tags/related_skills`) under `skills/` + `optional-skills/`, injected by `skill_commands.py`, composable via `skill_bundles.py`
- **Tech stack**
  - Inference & Orchestration: custom turn pipeline (no LangChain); `transports/` adapters (anthropic, bedrock, codex + App Server protocol, chat_completions, gemini_native); `credential_pool.py` per-model cooldowns; `moa_loop.py` (mixture-of-agents); terminal backends (local/Docker/SSH/Daytona/Singularity/Modal); MCP server exposing Hermes tools (`transports/hermes_tools_mcp_server.py`); ACP bridge; Docker Compose deploy
  - Voice & Vision: transcription registry (`local`, `local_command`, `groq`, `openai`, `mistral`, `xai`, `elevenlabs`, `deepinfra`); TTS registry (`edge`, `elevenlabs`, `openai`, `minimax`, `xai`, `mistral`, `gemini`, `neutts`, `kittentts`); vision via `vision_message_prep.py` (native turn images, no double-embedding)
  - Memory & Storage: `MemoryManager` + pluggable `MemoryProvider`; SQLite `SessionDB`; agent-curated capped markdown files; FTS5 full-text search; pluggable Honcho provider (`memory.provider: honcho`)
  - Integration: 263 tool modules in `tools/` (terminal, browser via Camofox/CDP/Lightpanda); approvals via `approval.py` + `approval_floors.py` (dangerous commands pause for human ALLOW/DENY); state in `~/.hermes/` (`config.yaml`, `state.db`, `MEMORY.md`/`USER.md`/`SOUL.md`)
- **Strength:** Self-improvement is a scheduled subsystem (reflect → curate → densify skill graph → agent-authored SKILL.md), and approval floors + sandboxing make it the closest thing here to a 24/7-safe agent
- **Bottleneck:** Python-monolith scale (~30 `turn_*.py` modules + plugin-compat shims); modifying core behavior needs deep familiarity, and it still wants a strong (usually cloud) model behind the adapters

### 2. open-jarvis/OpenJarvis (Stanford Hazy Research, Apache 2.0) — local-first agent framework

- **Pipeline**
  - Ingress: CLI (`jarvis ask`), FastAPI `server/`, desktop app, or 27+ channels (`channels/telegram.py`, `whatsapp.py`, `whatsapp_baileys.py`, `discord_channel.py`, `gmail.py`, `imessage_daemon.py`)
  - Voice: `speech/voice_io.py::record_until_silence()` (sounddevice, 16 kHz mono, RMS silence threshold 500, 1.5 s auto-stop, 30 s ceiling) → STT → text; push-to-talk, no wake-word engine
  - Tick: `AgentManager` → `agents/executor.py::AgentExecutor.execute_tick()` (`_MAX_RETRIES = 3`, events on `EventBus`)
  - Agent loops: `orchestrator` (OpenAI function-calling, `_default_max_turns = 10`, `parallel_tools = True`), `native_react` (text `Thought:/Action:/Action Input:/Final Answer:`; parser rejects responses containing both action and final answer), `native_openhands` (CodeAct), `simple`, `operative`/`monitor_operative` (continuous), `morning_digest` (scheduled), `deep_research`
  - Tools via `tool_resolver.py`; skills surface as `skill_*` tools with two taught return modes — *computed result* (use directly) vs *procedural instructions* (markdown playbook: follow with other tools, never re-call the skill); output streamed as SSE; tool results converted to a storage contract with per-tool latency in ms
  - Background: `daemon/` + `scheduler/` (natural-language cron); `learning/` (traces → SFT/GRPO; orchestrator's `structured` mode matches the training format)
- **Tech stack**
  - Inference & Orchestration: `InferenceEngine` abstraction over Ollama, vLLM, SGLang, llama.cpp, MLX, LM Studio, Exo, Nexa, Uzu, Lemonade, Apple Foundation Models, gemma.cpp + cloud via LiteLLM (`provider/model`, keys from env); `core/config.py::recommend_engine(hw)` / `recommend_model(hw)` RAM-tier table; `jarvis init` / `jarvis doctor`
  - Voice & Vision: STT `FasterWhisperBackend` (default `base`, lazy-load), `openai_whisper.py`, `deepgram.py`; TTS `KokoroTTSBackend` (local multilingual `KPipeline`), `cartesia_tts.py`, `openai_tts.py`
  - Memory & Storage: `LocalFactStore` — append-only JSONL, `max_facts = 1000`, atomic temp-file+rename, thread lock; `FactExtractor` on background thread (small local model, temp 0.0, strict JSON-array prompt; any failure → "no facts", never raises); RAG via SQLite/FAISS/ColBERT/BM25
  - Integration: `shell_exec`, `file_read/write`, `browser.py`/`browser_axtree.py`, `http_request`, `code_interpreter`, `mcp_adapter.py`, A2A (`a2a/`), Docker sandbox, skill importer with dependency resolution, Rust extension via maturin
- **Strength:** Cleanest separation of concerns in the survey; the only system treating local-model efficiency as a measurable target (evals on energy/FLOPs/latency/$)
- **Bottleneck:** Framework, not product (2,151 files); the default tick model `gemma4:31b` concedes the headline local model (`qwen3:8b`) fails the framework's own function-calling protocol on agentic workloads

### 3. FatihMakes "Mark-LIII" — Gemini Live + self-describing plugins + forgery-proof confirm

- **Pipeline**
  - Wake: `core/wake_word.py` on pretrained openwakeword ONNX `hey_jarvis` (`DEFAULT_THRESHOLD = 0.5`, own thread, non-blocking queue; `WAKE_SLEEP_TIMEOUT = 120.0` s auto-sleep) or global Ctrl+Space (`core/hotkey.py`); mic/speaker open once awake (sounddevice 16 kHz in / 24 kHz out, `CHUNK_SIZE = 1024`)
  - Session: `main.py::JarvisLive.__init__` → `discover_actions()` + `discover_plugins()` → `_build_config()` → `types.LiveConnectConfig`: `response_modalities=["AUDIO"]`, in/out audio transcription, `system_instruction` rendered at runtime from `core/prompt.txt` + memory + live-derived `{capabilities}`/`{limits}` (never hardcoded), `tools=[{function_declarations}]`, `SessionResumptionConfig`, `ContextWindowCompressionConfig(sliding_window)`, `PrebuiltVoiceConfig` (5 voices), `AutomaticActivityDetection`, `ProactivityConfig(proactive_audio=True)`
  - Audio loop: `receive()` coroutine owns mic; `send_realtime_input(audio=…)` streams chunks; `EchoGuard` (`core/echo.py`) band-energy subtraction (`_BAND_EDGES = 200…7000` Hz) + learned mic-to-output gain + `_TAIL_MARGIN = 0.25` s
  - Tool calls: `_execute_tool()` (`main.py:1113`) → inline core tools (incl. `save_memory`/`recall_memory` → `memory/long_term.json`: 6 categories, `MEMORY_MAX_CHARS=200_000` vs `PROMPT_CORE_CHARS=900` budget) or `action_registry`/`plugin_registry` with signature introspection injecting only declared context kwargs; each action/plugin declares `behavior: BLOCKING|NON_BLOCKING` + `scheduling: WHEN_IDLE|SILENT|INTERRUPT`; "instant acknowledgment" rule (model names the action before a gap forms)
  - Confirmation (`core/confirm.py`): irreversible actions call `request()` → on-screen CONFIRM/CANCEL banner, model gets a sentence to say; only the UI button calls `resolve()` on a worker thread (`TIMEOUT_SECONDS = 90.0`) — the model *cannot* forge approval (old `confirmed=yes` param convention explicitly documented as insecure); refuses if no UI bound; `core/undo.py` puts reversible changes on an undo stack instead of prompting
  - Background: `actions/background_monitor.py`, `proactive.py` (time-aware check-ins), `reminder.py` (OS-native Task Scheduler/LaunchAgent/systemd), `system_monitor.py` (`pynvml` GPU-temp spoken alerts); dashboard `dashboard/server.py` (FastAPI phone remote, QR pairing, `/api/command`, `/api/wake`, `/ws/phone-audio`, AES-CBC session auth, self-signed certs)
- **Tech stack**
  - Inference & Orchestration: single long-lived Gemini Live WebSocket (`models/gemini-3.1-flash-live-preview`, `google-genai>=2.8.0,<3`); hybrid paths `core/stt.py` (faster-whisper int8 CPU / Vosk), `core/tts.py` (EdgeTTS / offline Kokoro ~330 MB / ElevenLabs), `core/llm_client.py` (Ollama/LM Studio); `core/gemini.py` one-shot ladders (`FAST`/`SMART`/`SEARCH`)
  - Voice & Vision: sounddevice + numpy; visemes at `_VIS_HOP = 480` samples (~50 shapes/s) from formants (F1 openness, F2 width) + transcript closures → QPainter software head (`core/avatar.py`, `core/face_model.obj` MediaPipe canonical); PyQt6 HUD (`ui.py`, 5437 lines)
  - Memory & Storage: `memory/long_term.json` (6 categories); prompt budget separation (200k chars stored vs 900 injected)
  - Integration: plugins as `TOOL`/`PLUGIN` dicts auto-discovered at startup (name regex `^[a-zA-Z_][a-zA-Z0-9_]{0,63}$`, collisions logged-and-rejected); `pyautogui/pyperclip/pygetwindow/playwright/mss/opencv/psutil/ddgs/tinytuya`; Gmail/Calendar OAuth; Windows-only `pywinauto/pywin32/pycaw/wmi`; `setup.py`/`core/installer.py` OS autostart
- **Strength:** Zero-touch extensibility (one file in `actions/` or `plugins/` auto-registers tool schema + prompt rendering), and `confirm.py` is the rare *correct* answer to LLM self-approval
- **Bottleneck:** single module-global `_pending` confirmation — two racing irreversible actions overwrite each other; `WHEN_IDLE`/`SILENT`/`INTERRUPT` scheduling hints are advisory metadata with no client-side execution contract

### 4. eadmin2/jarvis_ai (MIT) — FastAPI voice server + Hermes Agent over HTTP/SSE + arc-reactor HUD

- **Pipeline**
  - HUD: `server/hud/index.html` (vanilla JS, single file) — click-the-ring → `getUserMedia` 16 kHz mono → inline `AudioWorkletProcessor` downsamples → 80 ms int16 frames over `/ws`; native client `client/client.py` (sounddevice + openwakeword `hey_jarvis` threshold 0.55 or push-to-talk) → same PCM to `:8765/ws`; wire protocol documented in `docs/ARCHITECTURE.md`
  - STT two-tier (`VoicePipelineServer.transcribe`, `server.py:302`): GPU worker `POST :8768/stt` (`worker/stt_server.py`: faster_whisper `large-v3-turbo`, cuda, fp16, `beam_size=1`) with silent fallback → local `RealtimeSTT.AudioToTextRecorder` (`small.en`, cpu, int8), constructed once per process behind a single `asyncio` `stt_lock` (STT globally serialized); partial captions via `_maybe_schedule_partial` every `stt.partial_interval` (1.2 s) re-transcribing the buffer
  - Agent: `HermesAPI` (`server.py:202`) → `http://127.0.0.1:8642`, `POST /api/sessions/{id}/chat/stream` (SSE) per turn, `/v1/runs/{id}/stop` for STOP, `/v1/runs/{id}/approval` for approvals; session ids persist in `server/logs/hermes_sessions.json`; `X-Hermes-Session-Key: jarvis:user:main` scopes long-term memory
  - SSE parse (`_parse_sse`): `run.started` → `assistant.delta` → `tool.started` (name + 200-char preview; `_`-prefixed pseudo-tools filtered) → `*approval*` → cards → `assistant.completed` → `run.completed` (tokens → `logs/usage_stats.json`); Hermes-down fallback: direct Anthropic `claude-haiku-4-5` (`max_tokens: 220`, temp 0.3) — memory-less, tool-less
  - Approvals: Hermes `*approval*` SSE → `approval_request{data,run_id}` → HUD ALLOW/DENY cards → decision POSTed to `/v1/runs/{id}/approval`
  - STOP/barge-in: cancels the asyncio turn task + `/v1/runs/{id}/stop`; barge-in records the last spoken sentence and injects a cut-off note into the persistent session so memory matches what the user heard
  - TTS: ElevenLabs `eleven_flash_v2_5` `/v1/text-to-speech/{voice_id}/stream?output_format=pcm_16000`, sentence-split streaming while the agent still generates (~3 s to first audio); secret redaction before cloud TTS
  - Deploy: two macOS LaunchAgents with hard-won `NumberOfFiles=8192` fix (server idles ~244 FDs; dies under launchd's 256 default); ports 8765 (WS), 8766/443 (TLS HUD), 9443 (dashboard proxy), 8767 (stats), 8768 (GPU STT)
- **Tech stack**
  - Inference & Orchestration: FastAPI + `requests` Hermes client over HTTP/SSE (not subprocess/SDK/MCP); `hermes-plugin/hud_display/` native plugin (`ctx.register_tool`) exposing `hud_display`/`hud_dismiss`, POSTing back to `/api/summon` over loopback
  - Voice & Vision: faster-whisper (CPU `small.en` int8 / remote `large-v3-turbo` fp16); RealtimeSTT `AudioToTextRecorder`; ElevenLabs Flash streaming; vanilla-JS HUD
  - Memory & Storage: delegated to Hermes sessions (`jarvis:user:main`); usage stats JSONL
  - Integration: loopback HTTP between voice server and agent process — the agent and the voice pipeline are separately deployable, restartable units
- **Strength:** Pipelined latency (sentence-split streaming TTS while generation continues, ~3 s to first audio) plus secret redaction pre-TTS and real deployment hardening
- **Bottleneck:** one `AudioToTextRecorder` behind one lock (partials and finals mutually block, no multi-user path); remote STT probed with a 6 s timeout per turn (degraded-but-reachable GPU worker = 6 s dead air); `ack_after_seconds`/`ack_texts` in `server.example.yaml` are dead config — long tool runs go silent

### 5. adewaskar/jarvis — browser face, Claude Code headless as the brain

- **Pipeline**
  - `src/App.tsx` → `src/lib/voice.ts`: one `SpeechRecognition` instance for the page lifetime (mic stays open while JARVIS talks → barge-in); wake `WAKE_ENGINE='porcupine'` if `VITE_PICOVOICE_ACCESS_KEY` (offline WASM) else `'speech'` — same stream scanned for `WAKE` regex with Jarvis aliases (`jarvys|jervis|travis|jarviss|java's|jarv`) since Chrome mishears the name; `onWake(trailing)` catches "Jarvis, what's the weather" in one breath
  - Endpointing: energy VAD (`vad.ts`) + assembler holding `CONTINUES` function words so mid-thought pauses don't split turns; modes `wake → command → guard`; extras: `clap.ts` transient detector (`PEAK_OVER_FLOOR=7`, `MIN_PEAK=0.055`), `hands.ts` MediaPipe WASM
  - Brain: `brain.ts::ask()` → `bridge.ts::ask()` → `ws://localhost:8787` `{type:'ask'}` → `bridge/server.mjs` → `@anthropic-ai/claude-agent-sdk` `query({prompt, model: JARVIS_MODEL ?? 'claude-opus-5', effort: 'high', maxTurns: 24, includePartialMessages: true, permissionMode: 'default', settingSources: []})` — `settingSources: []` blocks `~/.claude/settings.json` bypasses, then `~/.claude.json` `mcpServers` are re-injected by hand
  - Tool surface: Claude Code built-ins + all local MCP servers + 4 in-process servers (`jarvis` display/blade, `jarvis_ui` live Three.js restyle, `jarvis_chrome` driving the user's Chrome, `jarvis_eyes` camera)
  - Gate: `canUseTool` → `decideTool()`: `READ_ONLY_BUILTINS` vs `WRITE_BUILTINS` on `JARVIS_ALLOW_WRITES==='1'`; MCP names matched against `EFFECTFUL_VERB` regex (`send|delete|buy|deploy|…`), `READ_ONLY_MCP` allowlist, `READ_VERB` prefix regex — with the honest comment that deny is reliable but absence of a gate call proves nothing ran
  - Output: streamed `delta` frames → sentence-split `tts.ts` (single-pump queue cuttable for barge-in; `ECHO_TAIL_MS=1800` self-echo suppression; `fillers.ts` speaks ahead of tool calls); TTS = `speechSynthesis`, `kokoro-js` ONNX (`bm_george`), or ElevenLabs (`JBFqnCBsd6RMkjVDRZzb`); face: React 19 + three/fiber/drei + custom GLSL, zustand, mic level drives visualizer
- **Tech stack**
  - Inference & Orchestration: `@anthropic-ai/claude-agent-sdk@^0.3.220`; `ws@^8.21.1` bridge (`JARVIS_BRIDGE_PORT ?? 8787`); config via `VITE_BACKEND`/`VITE_TTS_ENGINE`/`VITE_KOKORO_VOICE`/`VITE_USE_ELEVENLABS`/`VITE_PICOVOICE_ACCESS_KEY`/`JARVIS_ALLOW_WRITES`/`JARVIS_MODEL`/`JARVIS_EFFORT`
  - Voice & Vision: Web Speech API (Google-server STT); `@picovoice/porcupine-web`; kokoro-js; MediaPipe tasks-vision
  - Memory & Storage: none of its own — inherits whatever the Claude Code session holds
  - Integration: piggybacks the user's existing Claude Code install and every stdio MCP server on the machine; zero new credentials
- **Strength:** Library-grade brain — running the coding agent you already have headless inherits every local MCP server with zero new credentials; sentence-level streaming TTS = low-latency-by-architecture
- **Bottleneck:** "the socket is the session" — one SDK `query()` per WebSocket, so any reconnect silently wipes conversational memory while the transcript still shows it; `maxTurns: 24` with no resume/continuation can kill long tool chains

### 6. mem0 (mem0ai/mem0, Apache 2.0) — LLM-driven memory layer, v3 phased pipeline

- **Pipeline** (`mem0/memory/main.py::Memory`)
  - `add(messages, user_id/agent_id/run_id, infer=True)` → `_add_to_vector_store()`: Phase 0 — `db.get_last_messages(session_scope, limit=10)`; Phase 1 — embed query, vector search `top_k=10`, map UUIDs→integer indices (anti-hallucination); Phase 2 — single LLM call emits ADD/UPDATE/DELETE/NOOP against numbered existing memories; Phase 3 — `_create_memory()` / `_update_memory()` / `_delete_memory()`; entity linking (`_upsert_entity`, `_link_entities_for_memory`)
  - `infer=False` stores verbatim; `search()` → `_search_vector_store()`: embed → filtered vector search → `_compute_entity_boosts()` → optional reranker (`threshold=0.1`); full CRUD + `history()`; every mutation journaled to SQLite `~/.mem0/history.db`
- **Tech stack**
  - Inference & Orchestration: `mem0/llms/` (default openai; anthropic, gemini, groq, deepseek, together, xai, ollama, vllm, lmstudio, litellm, langchain, azure, bedrock, minimax, sarvam + structured-output variants); `MemoryConfig` Pydantic; Python + TypeScript SDKs, REST `server/`, `proxy/` mode, `Memory.chat()`, MCP `integrations/`
  - Voice & Vision: none (memory substrate only)
  - Memory & Storage: vector stores — Qdrant (default), Chroma, pgvector, MongoDB, Redis, Elasticsearch, OpenSearch, Pinecone, Weaviate, Milvus, FAISS, Supabase, Upstash, Valkey; embeddings (openai, ollama, huggingface, fastembed, gemini, together, vertexai, azure, bedrock, lmstudio); entity graph via `_upsert_entity`/`_link_entities_for_memory`
  - Integration: drop-in `m.add()` / `m.search()`; widest vector-store matrix in the survey
- **Strength:** the phased add (retrieve-before-extract, single-call ADD/UPDATE/DELETE decisions, entity boosts) is the most token-efficient and update-correct design here — fixes the naive append-only embedding dump that lets long-running agents contradict themselves
- **Bottleneck:** an LLM judges every write (mis-extractions compound silently); heaviest cost-per-write option, and memory content routes through whichever LLM provider you configure

### 7. memU (NevaMind-AI/MemU, Apache 2.0) — memory-as-files service, LLM-free core

- **Pipeline**
  - Record seam: scheduled task runs `memu memorize` on the host's session log → `app/memorize/lifecycle.py::prepare_memorize()` materializes transcript → *host agent* distills memories/skills to Markdown ("judgment and synthesis stay inside the agent; `MemoryService` makes no LLM or chat calls") → `commit_memorize()` writes `RecallFile` rows (track `"memory"`|`"skill"`) + `Resource` rows, slices files into `RecallFileSegment`s (the embed unit); drop-and-recreate on re-slice
  - Inject seam: instruction-file standing order → `<binary> retrieve` → `AgenticMixin::progressive_retrieve()` (`app/agentic.py`): embed query → batched `_EmbeddingBatch` segment ranking → roll up to parent files → `_materialize_hits()` into context; cursor pagination
  - Install: `SKILL.md` (`name: install-memu`) routing skill → `pip install --upgrade memu-cli` → `memu-agent detect` → pick binary (`memu-codex`, `memu-claude-code`, `memu-cursor`, `memu-openclaw`, `memu-hermes`, `memu-workbuddy`, `memu-cola`, `memu-pi`, `memu-agent` in `hosts/`) → wire both seams behind verify gates
- **Tech stack**
  - Inference & Orchestration: none of its own — the connected agent does all synthesis
  - Voice & Vision: none
  - Memory & Storage: Pydantic models (`database/models.py`): `Resource` (url/local_path/caption/embedding), `RecallFile` (name/description/content/embedding), `RecallFileSegment` (recall_file_id/text/embedding); `Database` Protocol with inmemory/sqlite/postgres backends (`database/factory.py`); embeddings via OpenAI, Jina, Voyage, OpenRouter, Doubao (`embedding/backends/`); optional memU Cloud (`memu.so`) with sync/webhooks via memU-server + memU-ui
  - Integration: per-host adapter CLIs mine host session logs (Claude Code `~/.claude/projects/<project>/<session>.jsonl`, Codex, Cursor, OpenClaw, Hermes `~/.hermes/state.db` read-only) and patch instruction files (`CLAUDE.md`/`AGENTS.md`/`SOUL.md`)
- **Strength:** human-readable portable Markdown memory that survives provider pricing changes; ~500 lines of core logic, zero LLM calls = zero extraction cost/risk; one memory across heterogeneous harnesses
- **Bottleneck:** quality is entirely agent-dependent (weak agent → weak Markdown, no validation layer); retrieval is a single embedding pass with no rerank/graph, so relational queries underperform mem0-graph

### 8. Honcho (Plastic Labs, open-source) — reasoning-first memory

- **Pipeline**: the Honcho Loop — **Store** (raw conversations/events/tool traces as messages on `Workspace → Peers → Sessions → Messages`) → **Reason** (background loop updates a per-peer *representation* — an LLM-derived model of each participant: preferences, technical level, goals, drift over time; dialectic reasoning models what one peer knows about another) → **Query** (natural-language questions like "how technical is the user?", semantic search, peer cards) → **Inject** (drop result into any LLM call)
- **Tech stack**
  - Inference & Orchestration: background reasoning loop over any OpenAI-compatible LLM endpoint (Ollama/vLLM accepted → stays on-prem); managed alternative `api.honcho.dev`
  - Voice & Vision: none
  - Memory & Storage: PostgreSQL + pgvector (messages, representations, embeddings), Redis (caching); embeddings default `openai/text-embedding-3-small`, swappable (local BGE via vLLM)
  - Integration: Hermes provider (`hermes memory setup` → provider `honcho`; `memory.provider: honcho` in `~/.hermes/config.yaml`) — injects provider context into system prompt, prefetches relevant memories before each turn (background, non-blocking), syncs turns after each response, extracts on session end, mirrors `MEMORY.md`/`USER.md` writes; tools `honcho_profile`, `honcho_search`, `honcho_context`, `honcho_reasoning`, `honcho_conclude`; knobs `contextCadence` (1), `dialecticCadence` (2), `dialecticDepth` (1–3), `recallMode` (`hybrid`/`context`/`tools`), `writeFrequency` (`async`/`turn`/`session`/N)
- **Strength:** the only memory layer maintaining a *reasoned model of the user* rather than a fact pile — cross-session alignment works even when no single stored fact answers the question
- **Bottleneck:** heaviest self-host footprint (Postgres+pgvector, Redis, LLM, embedder — four services); dialectic LLM calls every N turns add latency/cost; representation drift is silent until manually corrected

### 9. alexcandothat's DIY stack — capture-to-graph-to-voice, "intelligence = context + relevancy"

- **Pipeline**
  - Capture: Plaud Note/NotePin records → pulled via unofficial `api.plaud.ai` REST (Bearer token lifted from logged-in `app.plaud.ai` session; EU `api-euc1.plaud.ai`): list files → download MP3/WAV → fetch transcript + AI summary (S3, gzip); fallback: folder-watching Plaud desktop export
  - Transcribe: faster-whisper (CTranslate2, int8-quantized Whisper `large-v3`, CPU on Mac Mini) → JSON timestamped segments + speaker diarization → cleaned Markdown
  - Store: transcripts land as Markdown in an Obsidian vault; entities become `[[wikilinked]]` notes — a plain-text link network on the filesystem (greppable, git-friendly, no DB)
  - Reason: Hermes Agent (v0.14) on Mac Mini — session memory, persistent `MEMORY.md`/`USER.md`, skill memory (auto-written reusable skill docs); reads the vault as files
  - Retrieve ("Fletcher"): embed query → rank notes/segments → inject top-k into the agent's working context — the relevance gate ("full recall would drown the model")
  - Voice: Raspberry Pi satellite (openWakeWord/Porcupine wake → audio to Mac Mini over HTTP/MQTT LAN → Piper TTS playback) → Amazon Echo as room endpoint (Alexa skill webhook / audio cast)
- **Tech stack**
  - Inference & Orchestration: Hermes Agent (Nous Research, MIT) on Mac Mini; model-agnostic
  - Voice & Vision: Plaud recorder; LocalWhisper (faster-whisper); Pi satellite + Echo endpoint; USB SSD storage (moved off microSD after the AI HAT covered the slot — Part 27)

### 1. Synthesized architecture blueprint

The control loop, top to bottom. Every stage names its source system.

- **Surfaces (ingress/egress)** — *Donna + eadmin2 + adewaskar + LiveKit*

  - STT: faster-whisper int8 locally for utterance privacy; Deepgram nova-3 streaming when sub-second partials matter (LiveKit path)

### 3. End-to-end execution trace

Command: **"Check my unread emails, extract travel dates, book a calendar slot, and dim the office lights."**

- **1. Ingress.** WhatsApp voice note arrives → WAHA/Baileys webhook POSTs `{from, type: audio}` → gateway verifies signature → maps `wa_id` → persistent agent session → immediate ack ("On it — checking email, calendar, and lights.")
- **2. Transcribe (edge).** Audio blob → ffmpeg → faster-whisper int8 (local) → transcript text; raw audio never leaves the host (*privacy tier*).
- **3. Triage.** Small local router classifies: multi-tool task (email read + entity extraction + calendar write + actuator) → escalates to the full agent runtime; prefetch fires in the background (non-blocking): warm memory (`honcho_context` — "user travels for FBA sourcing; prefers evening slots"; mem0 search "travel dates" — past trips, companions) + hot session (today's existing commitments).
- **4. Turn assembly.** Hermes `assemble_api_request()`: system prompt + `build_memory_context_block()` (travel preferences, home timezone America/Chicago) + skill payloads (gmail, calendar, home-assistant) → cloud frontier model via LiteLLM router (credential pool, per-model cooldown).
- **5. Plan.** Model emits a plan: (a) Gmail `users.messages.list` (`q=is:unread newer_than:7d`) → `batchGet` subjects/senders/snippets; (b) extract travel dates/entities; (c) find a free calendar slot honoring constraints; (d) dim office lights. Steps (a)+(d-probe) parallelized (`parallel_tools=True`).
- **6. Gather.** Gmail tool returns unread threads; Home Assistant queried for `light.office` current state (verification baseline). Idempotency key (message ID) recorded so a webhook retry can't double-execute.
- **7. Extract.** LLM reads the snippets → travel dates identified (e.g., "supplier visit Tue–Thu next week") → written to memory: mem0 `add()` (phased: dedup against existing trip facts, entity-link the supplier) + vault Markdown append (trip note, git-tracked).
- **8. Calendar.** `calendar.events.list` (`timeMin`/`timeMax` around the travel window) → free/busy → model proposes a slot; booking is an *external commitment* → approval tier: Donna-style inline keyboard in WhatsApp — "Hold Tue 2:00–3:30 PM for supplier-visit prep? [Approve] [Edit] [Reject]". Tool call pauses on the `callback_query` webhook.
- **9. Approve → execute.** User taps Approve → paused execution resumes → `calendar.events.insert` (with attendee + Meet link if needed) → observation: read the event back, confirm no collision.
- **10. Actuate.** `light.turn_off`/`light.turn_on` with brightness param → Home Assistant API/MQTT → observation: read back `light.office` state; mismatch → `error_classifier` → one retry, then escalate ("lights didn't respond — check the switch").
- **11. Verify.** Every step closes its observe loop: email list returned N threads, dates extracted and stored, calendar event exists (read-back ID), light state matches target. Nothing is reported as done without its evidence.
- **12. Brief.** Digest → WhatsApp text: "3 unread that matter (2 supplier, 1 bank), extracted Tue–Thu travel, held Tue 2:00–3:30 PM prep, office lights dimmed to 30%." Optional: Kokoro/Piper voice note with the same content if the user prefers audio; long version stays in chat.
- **13. Learn.** Post-task reflective phase → curator: reusable pattern ("travel-date extraction from supplier emails") proposed as a SKILL.md candidate; fact "office lights 30% = work mode" reinforced in warm memory; full audit entry (goal, trigger, context snapshot, plan, approval state, action log, verification, memory writes) appended to the job log.

### What was deliberately left out

- **Ghost X1 (uncensored model):** refusal-avoidance is the opposite of a trust architecture for a system touching messages, money, calendar, and home actuators. Excluded; model routing (hosted frontier + local specialist) covers the legitimate use cases.
- **Skit/funnel builds (Luke Azaris, Blake Stephens):** no reproducible internals — but their *interaction patterns* (overnight batch + morning brief; operator framing with approval gates) are load-bearing parts of the synthesis.
- **Single-purpose pieces** (hector clap trigger, nightfury Keras intents) contribute one component each (transient DSP detection; a cautionary tale about hardcoded intent taxonomies) rather than architectural roles.
