# Automation and Cases

Durable commitments, Cases, reminders and open loops survive chat closure, process restart, source gaps and transport failure. Capture ideas separately from decisions and binding commitments. A queued/sent/read message, expired job or silence never proves the business outcome.

The current implementation keeps server-owned planning/action materialization, canonical job/delivery generations and leases, requested reminders and bounded feedback/accountability. The richer Case graph, contextual automation and learned procedures remain phased targets with explicit input/source/authority/outcome contracts.

Use deterministic constraints before reasoning, preserve fixed external anchors, explain tradeoffs, group useful interventions and allow zero unsolicited interruptions. Quiet periods and explicit temporary owner override affect tactics without silently rewriting approved goals.

Model-generated automation is a procedure candidate. It needs source-backed prerequisites, tools/data scope, budgets, expected outcomes, failure/compensation, permission-preserving tests and review before promotion.
